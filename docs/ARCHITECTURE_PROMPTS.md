# SafeSKU architecture diagram prompts

## Product architecture prompt

Create a polished senior-engineering architecture diagram for **SafeSKU**, an evidence-grounded Amazon marketplace product-safety investigation platform. Use a clean white background, restrained blue/slate accents, precise AWS service icons, strong whitespace, and straight data-flow arrows. Organize the diagram left-to-right in six layers: **Source Data**, **Ingestion**, **Evidence Workspace**, **Safety Intelligence**, **Agentic Investigation**, **Human Decision**. Source Data should contain CPSC recalls, SaferProducts.gov incidents, Amazon product metadata and optional Amazon reviews. Ingestion should contain browser upload, presigned S3 upload, schema detection, validation, normalization, deduplication and SHA-256 fingerprinting. Evidence Workspace should contain S3 raw/immutable artifacts, DynamoDB control state and an evidence-backed canonical workspace. Safety Intelligence should contain product entity resolution, category-aware blocking, linkage scoring, temporal reasoning and evidence graph construction. Agentic Investigation should contain Amazon Bedrock, Strands Agents and explicit read-only tools for recall lookup, consumer-incident retrieval, marketplace candidate search, timeline construction and evidence verification. Human Decision should contain the investigator console, review queue, reviewer decision and safety case export. Make the key principle visually prominent at the bottom: **Source data is authoritative. Deterministic pipelines create evidence. AI orchestrates and explains. Humans resolve ambiguity.** The final visual should resemble an Amazon principal engineer architecture-review slide, not a generic AI infographic.

## Cloud data path prompt

Create a clean AWS deployment diagram for SafeSKU showing the exact production data path for a browser-uploaded safety bundle. Place the user and SafeSKU web console on the left, API Gateway and Lambda in the center, and S3 plus Step Functions plus ingestion Lambda on the right. Draw bundle bytes directly from the browser to S3 through a presigned PUT URL, and draw control requests from the browser to API Gateway. Show Step Functions invoking the ingestion Lambda, which reads the S3 bundle, validates the SafeSKU manifest, builds a canonical workspace snapshot and stores the immutable SQLite snapshot in S3. Show DynamoDB holding job status, current snapshot metadata, human review decisions and investigation history. Show Amazon Bedrock and Strands connected to the investigation API with read-only tools. Emphasize with a small annotation: **Data plane: S3. Control plane: API Gateway + DynamoDB. Workflow: Step Functions. Reasoning: Bedrock + Strands.** Use accurate AWS icons, no decorative illustrations, no crossed arrows, and enough whitespace to be readable in a three-minute hackathon demo.

## Investigation evidence-flow prompt

Create a technical evidence-flow diagram for SafeSKU. Start with one official CPSC recall on the far left. Branch into SaferProducts public incident records and Amazon marketplace product candidates. For each branch show concrete evidence fields such as recall number, incident date, publication date, ASIN, brand, model, UPC and product title. Merge these into a canonical product-identity node, then into a temporal reasoning node that calculates pre-recall public lead time, then into an evidence graph. On the next layer show a Strands agent selecting read-only investigation tools backed by the evidence graph. Finish at a human review gate with three explicit outcomes: **MATCH**, **NON_MATCH**, **UNCERTAIN**. Show that every conclusion points back to source evidence. Use a white background, subtle AWS blue accents, crisp typography and no cartoon graphics. Include a footer: **Evidence first. AI second. Human decisions stay explicit.**
