# Architecture diagram prompts

## 1. Main Build It architecture

Create a clean, senior software-engineering architecture diagram for **SafeSKU, an evidence-grounded Amazon marketplace product-safety investigation platform** running entirely on a developer machine under the AWS First Commit Build It track. Use a white background, restrained AWS blue and slate accents, precise service labels, strong whitespace, and simple arrows. Arrange the diagram in five horizontal layers: **User Product**, **AWS Open Source Runtime**, **Evidence Search**, **Safety Intelligence**, **Human Governance**. User Product should contain the SafeSKU Web Console with Data Workspace, Search, Investigation, Review Queue, and Export. AWS Open Source Runtime should contain AWS SAM Local, Strands Agents SDK, Cedar policy engine, and OpenSearch. Evidence Search should show OpenSearch indexing CPSC recalls, SaferProducts incidents, Amazon marketplace products, optional Amazon reviews, and SafeSKU linkage candidates. Safety Intelligence should contain entity resolution, temporal reasoning, evidence graph, and investigation tools. Human Governance should contain Cedar-authorized reviewer decisions and an immutable audit trail. Show Ollama with a local open model connected to Strands, explicitly labeled **local model, no cloud call**. Show SQLite as the structured source-of-truth workspace. Add a small footer: **Source data is authoritative. Search retrieves evidence. Strands orchestrates read-only investigation. Cedar guards human decisions.** Make it look like an Amazon architecture-review slide, not an AI infographic.

## 2. Investigation sequence

Create a clean sequence diagram showing one SafeSKU investigation from user request to evidence-backed case. Participants: User, SafeSKU API via SAM Local, OpenSearch, Workspace SQLite, Strands Agent, Ollama local model, Cedar. Flow: User searches a recall, API retrieves candidate evidence from OpenSearch and SQLite, Strands calls read-only investigation tools, Ollama reasons over returned evidence, API assembles the safety case, and Cedar authorizes or denies the human identity-review action. Visually distinguish AI reasoning from source-of-truth evidence and make the human decision the final step.
