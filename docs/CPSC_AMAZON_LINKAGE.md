# SafeSKU CPSC -> Amazon Product Linkage

## Purpose

This stage connects recalled CPSC products to Amazon catalog entities.

We deliberately do **not** ingest the Amazon review corpus yet. The Amazon Reviews'23 release is extremely large, so we first determine which Amazon products can be linked to the CPSC recall population.

## Current Amazon data

The first acquisition contains the `Appliances` and `Baby_Products` metadata categories.

The normalized metadata is keyed by `parent_asin`. Raw source files remain outside Git.

## Candidate policy

For the initial coverage audit, a CPSC product can generate Amazon candidates through:

1. exact normalized UPC, or
2. at least two shared product-name tokens using the rarest available CPSC tokens.

The candidate generator records the blocking source and keeps the complete candidate count before any review-output truncation.

This is a **candidate generator**, not the final matcher.

## Commands

Run candidate generation:

```powershell
python scripts\build_cpsc_amazon_candidates.py
```

Run coverage report:

```powershell
python scripts\profile_cpsc_amazon_coverage.py
```

The output is:

`data/benchmark/amazon_linkage/candidates.jsonl`

and:

`data/benchmark/amazon_linkage/candidate_manifest.json`

## What we decide from the coverage report

We will inspect:

- recalls with at least one candidate
- exact UPC coverage
- candidate-count distribution
- high-volume ambiguous recalls

Only after we know this coverage will we decide whether another Amazon metadata category is needed.

## Why we do not download reviews yet

Reviews are evidence attached to Amazon products. If product identity is wrong, review evidence can be attached to the wrong recall.

Therefore:

CPSC recall -> Amazon product identity -> Amazon reviews

is the required order.

## Research integrity

Candidate generation is intentionally broader than the final linkage model. Non-matching candidates must not be treated as negatives merely because they were generated by blocking.
